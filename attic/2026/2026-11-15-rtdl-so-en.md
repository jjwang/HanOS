# 2026-11-15: Add the runtime linker and shared objects

Load `PT_INTERP` binaries through the shared musl loader.

## Kernel

- `elf_load` maps an `ET_DYN` interpreter at the fixed runtime-linker base and passes `AT_BASE` in the auxiliary vector.
- The auxiliary vector uses the Linux keys: `AT_PHDR`, `AT_PHENT`, `AT_PHNUM`, `AT_BASE`, `AT_ENTRY`.
- Static executables without `PT_PHDR` publish `AT_PHNUM=0`; the interpreter does not read a null program-header table.
- `mmap` accepts file-backed mappings. A per-process cache reads the file once and serves page-aligned slices.
- Add the legacy `open` syscall and a `mprotect` syscall. The loader calls both while relocating a shared object.

## Image

- `/lib/ld-musl-x86_64.so.1` and `/lib/libc.so` come from the shared musl build.
- Static servers and applications remain the default. A dynamic executable sets `PT_INTERP=/lib/ld-musl-x86_64.so.1`.
- `make initrd` packages both files under `lib`.

## BFD assertion

- binutils 2.35 asserts in `bfd/elflink.c:14788`, `elf_append_rela`, when linking `-mcmodel=large` PIC shared objects. The relocation count exceeds the allocated `.rela.dyn` size.
- The assertion remains after removing `--gc-sections`, `--exclude-libs`, `--dynamic-list`, `--hash-style` and `--no-undefined`.
- Build the loader with `-mcmodel=small`; user binaries keep `-mcmodel=large`.
- `3rdparty/musl/build-shared.sh` compiles with `x86_64-elf-gcc` and links with `x86_64-elf-ld`. It does not use the host gcc.

## Tests

- A dynamic hello runs through the shared loader.
- A dynamic executable loads `libgreet.so` through `mmap` and prints `shared greet`.
- Static boot and CI still pass.
