50/*
51 * User Mode Refer:
52 * http://jamesmolloy.co.uk/tutorial_html/10.-User%20Mode.html
53 *
54 * The x86 is strange in that there is no direct way to switch to user mode. The
55 * only way one can reach user mode is to return from an exception that began in
56 * user mode. The only method of getting there in the first place is to set up the
57 * stack as if an exception in user mode had occurred, then executing an exception
58 * return instruction (IRET).
59 *
60 * - The instruction to continue execution at - the value of EIP.
61 * - The code segment selector to change to.
62 * - The value of the EFLAGS register to load.
63 * - The stack pointer to load.
64 * - The stack segment selector to change to.
65 *
66 * The EIP, EFLAGS and ESP register values should be easy to work out, but the
67 * CS and SS values are slightly more difficult.
68 *
69 * When we set up our GDT we set up 5 selectors - the NULL selector, a code segment
70 * selector for kernel mode, a data segment selector for kernel mode, a code
71 * segment selector for user mode, and a data segment selector for user mode.
72 *
73 * They are all 8 bytes in size, so the selector indices are:
74 *
75 * - 0x00: Null descriptor
76 * - 0x08: Kernel code segment
77 * - 0x10: Kernel data segment
78 * - 0x18: User code segment
79 * - 0x20: User data segment
80 *
81 * For user mode we want to use selectors 0x18 and 0x20. However, it's not quite
82 * that straightforward. Because the selectors are all 8 bytes in size, the two
83 * least significant bits of the selector will always be zero. Intel use these
84 * two bits to represent the RPL - the Requested Privilege Level. These have
85 * currently been zero because we were operating in ring 0, but now that we want
86 * to move to ring three we must set them to '3'. If you wish to know more about
87 * the RPL and segmentation in general, you should read the intel manuals. There
88 * is far too much information for me to explain everything here.
89 *
90 * So, this means that our code segment selector will be (0x18 | 0x3 = 0x1b), and
91 * our data segment selector will be (0x20 | 0x3 = 0x23).
92 *
93 */
94#define DEFAULT_UMODE_DATA 0b00111011 /* 0x3b */
95#define DEFAULT_UMODE_CODE 0b01000011 /* 0x43 */

97/* ----- EFLAGS Register -----
98 * 0 CF Carry flag
99 * 2 PF Parity flag
100 * 4 AF Auxiliary flag
101 * 6 ZF Zero flag
102 * 7 SF Sign flag
103 * 8 TF Trap flag
104 * 9 IF Interrupt enable flag
105 * 10 DF Direction flag
106 * 11 OF Overflow flag
107 * 12-13 IOPL I/O privilege level
108 * 14 NT Nested process flag
109 * 16 RF Resume flag
110 * 17 VM Virtual 8086 mode flag
111 * 18 AC Alignment check
112 * 19 VIF Virtual interrupt flag
113 * 20 VIP Virtual interrupt pending
114 * 21 ID Able to use CPUID instruction
115 *
116 * You may notice that we disabled interrupts before starting the mode switch. A
117 * problem now occurs - how do we re-enable interrupts? You'll find that
118 * executing sti in user mode will cause a general protection fault, however if
119 * we enable interrupts before we do our IRET, we may be interrupted at a bad
120 * time.
121 *
122 * A solution presents itself if you know how the sti and cli instructions work
123 * - they just set the 'IF' flag in EFLAGS. Wikipedia tells us that the IF flag
124 * has a mask of 0x200, so what you could do, is insert these lines just after
125 * the 'pushf' in the asm above:
126 *
127 * pop %eax ; Get EFLAGS back into EAX. The only way to read EFLAGS is to pushf
128 * ; then pop.
129 * or %eax, $0x200 ; Set the IF flag.
130 * push %eax ; Push the new EFLAGS value back onto the stack.
131 *
132 */
133#define DEFAULT_RFLAGS 0b0000001000000010 /* 0x0202 */
